# 抓取与筛选

## 上游衔接

读取本机 google-maps-scraper/SKILL.md。按上游流程刷新一次、再读入口；联网失败按其恢复方式使用可用版本并记录。
本包不复制上游代码，不覆盖其代理、更新、运行约束。记录版本、可读取的镜像标识、查询、时间、数量、退出状态至 work/crawl-manifest.json。
当前上游用 scripts/run-local.sh 和 scripts/status-local.mjs；最终以已安装版本接口为准。
查询和原始结果保存到 RUN/work，或把上游临时目录产物复制回来。
先一个代表查询浅层验证；退出成功且有至少一条数据再继续。保守并发，不为凑数无限扩抓。
固定容器名不能同时启动两轮；不得停止另一个任务。先抓基本字段，仅确实需要时增加邮箱或评论提取。

## 导入与初筛

`workflow.py normalize --input RAW --out RUN/work/pool.json` 支持 CSV、JSON 数组、results 数组对象与 JSON Lines。
place_id/cid 优先去重，再用地图 URL、店名与地址；仅共享域名或电话不能合并分店。
emails_unverified 只是线索，不自动成为已核实收件人。
访问官网首页和主要联系入口，评估具体机会：手机溢出、预约层级深、主营业务难找、产品展示不足、联系按钮失效等。
风格陈旧不能证明低转化；评分高不等于有预算；不推断财务或付费意愿。
网站状态用 reviewed/unreachable/not_found/not_reviewed。抓取没有网址只支持“未找到”，不等于确实没有网站。

## 呈现

每家统一：编号、名称、行业、区域地址、地图/官网、评分/评论数、经营观察、网站状态、Demo 切入点、
联系情况、优先级及理由、待核实项。关键事实链接和时间可核查，推测明确标记。
呈现至多五家，数量不足提供覆盖说明及扩大建议。引导选编号/店名或换一批。
此阶段不写商家邮件或建 Demo。用户已明确指定商家时保存来源与选择，不人为补齐其他候选。

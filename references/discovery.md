# 抓取与筛选

## 默认执行入口

读取安装回执、runtime.json 和上游 google-maps-scraper/SKILL.md 的当前版本。
本包的 run_maps.py 是为 Codex 安装环境提供的适配入口，直接调用上游 Docker CLI，统一处理路径、代理、WSL 保活与结果检查；日常获客与安装验收使用同一入口。
按本包已保存的配置执行，不每轮升级上游或重置已选网络。需要更新时通过完整安装入口更新并重新验收。1.1.0 在上游 Skill 1.12.1 的接口下验证；若接口变化，先做浅层验证，不能直接扩大抓取。

以区域和行业形成一个代表查询，执行：

```sh
python "SKILL_DIR/scripts/run_maps.py" --query "bakeries in Manchester UK" --output-dir "RUN/work/crawl-01"
```

PROFILE 非默认时加 --profile。Windows 用主机 Python，入口自动调用保存的 WSL；不直接用 Windows Bash 执行上游脚本。
默认 CSV、深度1、并发1、不提取邮箱、不额外读取评论全文。抓取已覆盖需求时直接使用，不机械地再抓一遍。确有覆盖不足才针对区域/关键词追加；每次新输出目录，最多一次针对失败原因的重试，不无限扩抓。
原始数据与 crawl.json 保存到 RUN/work；非零退出、超时、空文件/空表均不算完成。禁止停止其他任务、输出原始代理日志。

## 评分和评价是必查项

初筛必须自动查看每家的地图评分、评论数、地图链接及核实时间，不能只看官网后把评分检查留给用户。
缺少字段时先检查原始 CSV，必要时打开对应地图商家页补查；页面阻断或商家确实无评价时如实标记“未核实”或“暂无评价”，说明尝试过的路径。不要编造数字或把抓取空字段等同于零条评价。
地图抓取整体失败时，明确告知环境或网络阻塞及恢复动作；官网初筛只能标为临时线索，不表述为完成了地图候选研究。
评分/评论数不等于评价正文。对最终候选尽量查看近期及低分评价，记录能读取的样本、时间和来源，区分经营问题与网站机会；不能仅凭星级编造好评/差评主题。选定客户后再次深入阅读相关评价。
确实需要批量评价正文时使用 `--format json --extra-reviews`，先小范围验证。不要对整个区域默认开启大量全文提取。

## 导入和网站初筛

`workflow.py normalize --input RAW --out RUN/work/pool.json` 支持 CSV、JSON 数组、results 数组对象与 JSON Lines。
place_id/cid 优先去重，再用地图 URL、店名与地址；共享域名或电话不能合并分店。emails_unverified 只是线索，不能直接视为已核实收件人。
访问官网首页和主要联系入口，记录具体机会：手机溢出、预约层级深、主营业务难找、产品展示不足、联系按钮失效等。风格陈旧不能证明低转化，评分高不等于有预算，不推断财务或付费意愿。
网站状态用 reviewed/unreachable/not_found/not_reviewed。抓取没有网址只支持“未找到”，不等于确实没有官网。

## 候选呈现

每家统一展示：编号、名称、行业、区域地址、地图/官网、评分/评论数、评价观察及可读样本限制、经营观察、网站状态、Demo 切入点、联系情况、优先级/理由、待核实项。
关键事实链接和时间可核查，推测明确标记。呈现至多五家，不足时说明覆盖与扩大建议。引导选择编号/店名或换一批。
此阶段不建 Demo 或写商家邮件。用户已明确指定商家时保存来源和选择，不人为补齐其他候选。

# Demo 制作与检查

## 起步与实现

三个无构建静态起点：catalog 产品预订、booking 服务预约、quote 服务询价。
scaffold 在批准方案后复制 assets/demo-base/ 并生成转义的 config.js。配置来自实际研究，不得保留虚构示例。
地址缺失时可明确写“Address not verified in this concept”，不编造地址、价格、员工或客户评价。
模板提供结构和本地交互，仍需按批准方案完成品牌、素材和业务设计。不要所有商家都保持同一最终版式。
默认无外部字体/CDN/服务器调用，CSS 抽象装饰不冒充产品照片。
预览：`python -m http.server PORT --bind 127.0.0.1 --directory RUN/demo`。选择可用端口并保存进程句柄，
不扫描所有端口、不停止其他服务。工具支持时在 Codex 打开本地预览；localhost 不可当商家分享链接。

## 三种核心旅程

- catalog：选择一个产品、日期与时间窗，预览取货意向。
- booking：选择服务、日期与时段，预览预约意向。
- quote：选择服务、日期与项目规模，预览询价意向。

这些起点不是多商品购物车或真实日历。批准方案要求更多时实现后再交付，disabled 按钮不算完成。
默认不收集真实个人信息或支付数据，不连接商家真实提交接口。展示独立概念及模拟声明。
素材记录来源和用途。必要时使用可用图像工具，但最终邮件截图必须取自完成的 Demo。

## 验证

实测：加载 → 选择 → 日期/选项 → 摘要结果；空值和过去日期不产生假成功；无真实网络提交。
查看桌面和手机，检查横向溢出、截断、按钮、图片、焦点和实际内容。
截图放 RUN/screenshots，不能放进 demo 源码目录。第一张为邮件主图，选择清晰首屏或紧凑整体图，不默认嵌入极长截图。
备用截图：`node SKILL_DIR/scripts/capture.mjs --url http://127.0.0.1:PORT --out RUN/screenshots --module ACTUAL_PLAYWRIGHT_INDEX`
可用 --executable 指向实际 Chromium 路径；不读取用户浏览器登录资料。脚本报告视口溢出和 JS 异常，不能替代视觉和交互检查。
demo-ready 保存证据、源码和截图摘要；它记录检查断言，不能证明断言真实。
网站修改后旧记录失效，重做相关检查和截图再记录、生成新邮件。

## 可选发布

仅按用户批准的分享要求进行。Sites 可用时读取其 building/hosting 规则，其他指定平台按用户要求。
只发布网站运行文件，不上传整个 RUN，因为 work/records/邮件包含研究和身份资料。
发布成功不保证免登录访问；核实实际 audience，工具允许时用无登录上下文检查。
遵守工具限制，无法获得外部访问证据则 verified=false，邮件待补链接。用户已批准公开分享时不重复问同一授权。
无托管能力保留本地成果，不要求作者提供服务器。

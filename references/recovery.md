# 恢复规则

| 情况 | 行为 |
| --- | --- |
| 缺少抓取依赖 | 保存条件、诊断环境、指明设置，不声称已有真实线索 |
| 零结果 | 检查查询和状态，最多一次针对原因的验证重试，再请求调整范围或环境 |
| 上游已有重试 | 遵循其次数，不外层无限叠加 |
| 验证码/阻断 | 保留部分结果、报告限制，不绕过验证 |
| 官网打不开 | 标 unreachable、研究其他来源，不假装已做手机诊断 |
| 不足五家 | 呈现实际数量与覆盖说明 |
| 无邮箱 | 提供真实联系入口，邮件待补收件人 |
| 无图片生成 | 使用现有素材或明确示意，不影响真实 Demo 截图 |
| 无法截图 | 尝试备用工具，仍失败则保存 Demo 并明确缺附图，不登记 demo-ready |
| 无托管/私有 URL | 本地成果可交付，邮件待补分享链接 |
| 摘要变化 | 检查原因、重新保存对应阶段，不直接改 state 绕过检查 |
| 中断 | resume 后按当前引用继续，不承诺后台运行 |

换客户、方案、Demo 时保留旧文件，但旧文件不再作为当前成果。不要删除项目掩盖冲突。
同一 RUN 串行修改，不同 RUN 抓取仍遵循上游容器互斥。
脚本异常保留输入、错误摘要与现场，针对原因修复后再试，不改变事实以凑过校验。
